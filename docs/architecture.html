1Folder layout

The repo has four top-level folders you'll actually work in: the Python package, the extension source, the VM image, and the Tauri apps. Everything else (docs/, scripts/, archive/) is support.

  • inspekt/ repo root
    • inspekt/ python pkg the CLI, bridge, services, scripts (core product)
      • app/cli/ 45 Click command modules — entry: inspekt = inspekt.app.cli:main
      • app/api/ FastAPI surface
      • app/mcp/ MCP server exposing 33 tools to Claude Desktop
      • bridge_ws.py WebSocket broker — browser ⇄ CLI (ports 8765 host / 8767 VM)
      • client.py BridgeClient — transport-agnostic HTTP/socket client
      • config.py get_bridge_port() — single source of truth for the port
      • services/ ~79 modules: browser control, a11y, extraction, AI…
      • scripts/ 65+ JS files injected into the browser (DOM, axe, record, replay)
      • man/ pre-built man pages (shipped with the wheel)
    • extensions/ browser ext single source of truth — one repo, three sinks
      • chrome/ MV3 — service worker, DevTools panel, offscreen document
      • firefox/ MV2 — persistent background page
      • shared/ permissions, websocket-client, main-world-bridge
    • vm/ docker image the actual virtual browser — Alpine + Chromium + noVNC + supervisord
      • Dockerfile multi-stage: bun-bundle → alpine runtime (self-bundles assets)
      • control-panel.html 1400-line SPA served at :6080/control.html
      • servers/ control-server (8888), terminal-server (8889)
      • variants/headless/ stripped-down variant (no noVNC)
    • apps/ thin native shells around the core
      • desktop/ tauri native wrapper around the VM control panel (Svelte launcher + WKWebView)
      • pdf-viewer/ tauri PDF accessibility report viewer (separate app)
    • scripts/ build tools bundle-vm.mjs, bump_version.py, watch-extensions.js, build_man.py
    • docs/ mkdocs you're reading docs/architecture.html
    • Makefile entry single source of truth for every command — see §5-8
    • VERSION semver one file, 9 manifests follow — see §7
    • Procfile.dev process list for make dev-all (overmind)
    • pyproject.toml py console script + deps

Why is there an outer inspekt/ and an inner inspekt/? The outer is the git repo; the inner is the importable Python package. This is standard Python convention — same as requests/requests/.

2Three execution modes

Every mode funnels through the same bridge_ws.py server and the same extension code. What changes is where the browser runs and who sends commands.

1CLI + your browser

You install the extension in your own Chrome/Firefox. CLI runs on host.

terminal └─ inspekt <cmd> └─ BridgeClient (HTTP) └─ bridge_ws.py :8765 └─ WebSocket → extension └─ MAIN-world JS → DOM
Start: inspekt start (or make dev-cli). Extension: manually load-unpacked.

2Control panel + VM

Browser lives inside Docker. You point any browser at :6080.

any browser → :6080 └─ control-panel.html └─ fetch :8888/inspekt/<cmd> └─ control-server.py └─ inspekt CLI (in container) └─ bridge_ws.py :8767 └─ WS → bundled extension └─ Chromium (via VNC)
Start: make vm-start. Ports: noVNC 6080, control 8888, bridge 8767, CDP 9222.

3Tauri desktop + VM

Native window around the same URL as mode 2, plus OS integrations.

Tauri launcher (Svelte :1421) └─ check_docker / start VM └─ main window → WKWebView loads :6080/control.html └─ (same stack as Mode 2) + __TAURI_INTERNALS__ (clipboard, drag, notify)
Start: make dev-desktop. Permissions in apps/desktop/src-tauri/capabilities/clipboard-remote.json.

3How the extension reaches each mode

One source (extensions/chrome/, extensions/firefox/), three sinks at runtime. Keeping them in sync is what the new make sync-extension and make verify-extension-sync targets are for.

4Setup — once per machine

📦Python side

# clone and enter
git clone https://github.com/roelvangils/inspekt
cd inspekt

# install in dev mode with all extras
make dev

# or manually:
pip install -e ".[dev]"

Uses your active virtualenv. make dev is equivalent to pip install -e ".[dev]" plus a friendly reminder to run make pre-commit.

🛠Host prerequisites

# on macOS (homebrew)
brew install docker bun overmind

# optional but recommended
brew install pandoc      # for make build-man
cargo install cargo      # for tauri builds

overmind only needed for make dev-all. bun is required for the VM bundle step and the Tauri apps. docker must be running before any VM command.

5Install the browser extension

🧭Chrome / Edge / Brave dev mode

# 1. Open the extensions page
open chrome://extensions

# 2. Toggle "Developer mode" (top-right)

# 3. Click "Load unpacked" and pick:
/path/to/inspekt/extensions/chrome

# 4. Start the bridge on the host:
inspekt start

# 5. Visit any site → extension icon lights up

Reload the extension (⟳ button on the card) whenever you edit files in extensions/chrome/. Use make dev-extension for a watcher that prints the reload hint on each change.

🦊Firefox temporary add-on

# 1. Open the debug page
open about:debugging#/runtime/this-firefox

# 2. Click "Load Temporary Add-on…"

# 3. Pick the manifest:
/path/to/inspekt/extensions/firefox/manifest.json

# 4. Start the bridge:
inspekt start

Temporary add-ons disappear on restart. That's a Firefox constraint, not ours — use the Chrome workflow for a persistent dev install, or make build-extensions for a signable xpi.

📦Release zips

make build-extensions
# → dist/inspekt-chrome-1.0.0.zip
# → dist/inspekt-firefox-1.0.0.zip

Ready for Chrome Web Store / Firefox Add-ons submission. The version in the zip filename comes from VERSION — bump it with make version NEW=x.y.z first.

🐳Inside the VM

# the Docker image already bundles the extension.
# to propagate changes after editing:

# soft (no rebuild, seconds):
make sync-extension

# hard (full image rebuild, ~5 min):
make build-vm

# verify host == container:
make verify-extension-sync

sync-extension does docker cp + restarts Chromium. It's the right tool 95% of the time.

8Versioning

🏷Bump everything at once

make version NEW=1.1.0

Writes the new value to VERSION and propagates to every manifest:

pyproject.toml
extensions/chrome/manifest.json
extensions/firefox/manifest.json
apps/desktop/package.json
apps/desktop/src-tauri/tauri.conf.json
apps/desktop/src-tauri/Cargo.toml
apps/pdf-viewer/package.json
apps/pdf-viewer/src-tauri/tauri.conf.json
apps/pdf-viewer/src-tauri/Cargo.toml

🔧Under the hood

Implemented in scripts/bump_version.py. Uses targeted regex per file (not full TOML/JSON reserialize) so diff noise stays zero. Idempotent — running twice is a no-op.

# idempotency check
python scripts/bump_version.py
# → already at 1.0.0

To check all versions agree right now: make doctor reads each one.

🔍make verify-extension-sync

make verify-extension-sync
# ✓ extension in sync (d71a516138b26c95)
# or:
# ✗ drift: host=abc vm=def
#   run: make sync-extension

Hashes every file in extensions/chrome/ on both host and container. Portable — uses find + shasum, works across bsd-tar and gnu-tar.

Quick reference — one-screen cheat sheet

⚡From zero to running — first-time setup

1make dev                              # install Python pkg editable
2inspekt start                         # start bridge daemon
3# load extensions/chrome/ unpacked in Chrome (see §5)
4inspekt display info                  # smoke test — should return page info

# or, for Mode 2 / Mode 3:
1make dev
2make vm-start                          # Mode 2 — open http://localhost:6080/
3make dev-desktop                       # Mode 3 — native window

🚀Daily drivers

make dev-all             # all four dev loops (overmind)
make doctor              # sanity-check state
make sync-extension      # push ext changes to VM
make vm-restart-control  # hot-swap control-server
make all                 # format + lint + typecheck + test

📤Release

make version NEW=1.1.0  # bump all manifests
make build-all           # produce every artifact
ls dist/                  # wheel + ext zips
ls apps/desktop/src-tauri/target/release/bundle
